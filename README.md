# 先算配速再开跑（pace-split）

手上只有一个成绩（比如 10 公里 50:00），换到另一段距离（5 公里 / 10 公里 / 半马 / 全马 / 自定）要跑多久、
平均每公里多少、**每段该跑到多少**、前半程压慢一点后半程要跑多少。

- 页面：`index.html`（单文件，离线可用，不联网、不内置任何成绩库）
- 引擎：`core.js`（纯函数，浏览器与 node 通用；`window.AppCore`）
- 界面：`ui.js` + `template.html`，`node build.cjs` 合成 `index.html`
- 测试：`node --test tests/core.test.cjs`
- 浏览器验收：`node 验收脚本.cjs --tag 本地`（或 `--tag 线上 --url <线上地址>`）
- 封面：`node make-cover.cjs`（1200×1200，数字全部来自同一次引擎输出，落盘 `evidence/封面取值.json`）

## 模型（全部写在页面上）

1. **幂律外推**：`T₂ = T₁ × (D₂/D₁)^k`；等价写法 `p₂ = p₁ × (D₂/D₁)^(k−1)`。`k = 1` 时就是「配速不变、按距离线性放大」。
2. **配速与速度**：`p = T ÷ D`（秒/单位距离）；`v = 3600 ÷ p`（p 用秒/公里时 v 是 km/h）；
   `分钟/英里 = 分钟/公里 × 1.609344`（1 英里 = 1.609344 公里）。
3. **分段**：每 g 一段（末段可不满）。匀速时每段用时 = 段距离 × 平均配速；
   负分段时前半程配速 `p_A = p̄(1+x)`、后半程 `p_B = p̄(1−x)`，于是 `(D₂/2)·p_A + (D₂/2)·p_B = T₂` 精确成立；
   跨过半程点的那一段按段内前后半各自的距离分别计时；半程点累计时间 = `T₂(1+x)/2`。
4. **反推**：目标时间 → 所需平均配速；同一条幂律反解回 `D₁` 应当精确得到 `T₁`（页面把它当自检项）。
5. **显示**：秒数四舍五入，累计时间按未取整的全精度值求和。

`k = 1.06` 是本页的默认值，只是一个可调旋钮：本页不引用任何研究或他人成绩来论证它，换成 1.00 / 1.10 照算。

## 不做的事

不是训练计划；不含坡度、海拔、天气、赛道、补给、心率、步频；不做力量与恢复建议；不做医疗与安全建议；
不联网、不查任何赛事或他人成绩、不内置任何成绩库、不与任何设备或 App 对接；除公里与英里之外不做其它单位换算。
默认场景与 9 个内置场景全部是**虚构示例**，不代表任何真实跑者、赛事或成绩分布。
目标距离超过已知距离 3 倍时页面会提示幂律外推误差会放大 —— 如实提示，不做修正。
